# Indev 19.3 校服维护与客户端安装

玩家和维护人员使用同一个 SAUMCL。入口在「设置 → 校服维护」，维护人员粘贴 Key 或导入 `.saumclkey` 文件后解锁。

## 已确定的授权规则

- 每名维护人员独立签发，默认长期有效，不设到期时间。
- 不绑定校服版本、整合包版本、启动器版本、电脑或当前维护人员名单。
- 校服升级、人员交接时，旧 Key 继续有效；后续构建须保留已使用的公钥及格式验证逻辑。
- 「退出维护模式」只删除本机授权，不使原 Key 作废；重新输入即可恢复。
- 公钥清单支持追加。增加新签名公钥时保留旧项，不覆盖或自动删除旧项。
- Key 只开放本地维护工具；GitHub 写入与公开发布仍需仓库权限。

## 原型功能与边界

维护页分为校服配置、整合包、公告与状态、导出预览四栏。可以编辑校服名称和地址、Minecraft / 加载器版本、整合包版本与下载地址、公告与维护状态、当前 / 下一周目及统一离线起始时间；支持保存本地草稿、应用到本机预览并导出 JSON。下一周目默认 20，可由维护人员修改。

本轮保存及导出均只操作本地草稿。「应用到本机预览」会保存草稿，并让本机启动页显示该配置；退出维护模式后，预览不再生效。它不会向其他玩家发布配置或创建 Release。校服地址每周目由维护人员填写，不固化在代码中。一键进入校服入口统一放在置顶校服行，带文字；右下角不再重复显示该按钮。

## 一键进入校服

填写整合包下载地址与版本后，点击「一键进入校服」会检查本周目客户端，首次自动下载、校验、安装客户端、加载器和缺少的 Java，完成后启动游戏并连接校服。现代版本沿用 `--quickPlayMultiplayer`（[官方参数说明](https://feedback.minecraft.net/hc/en-us/articles/16499677456781-Minecraft-Java-Edition-1-20-Trails-Tales)），旧版沿用 `--server` / `--port`，无需再点击多人游戏或预先保存服务器。

- 按维护配置筛选 Minecraft 版本、加载器及已填写的加载器 / 整合包版本。加载器「无」对应原版；Forge 支持现有 Forge、LegacyForge 与 Cleanroom 实例。版本号按实例元数据精确匹配；未填写的版本字段不作限制。这不代替模组文件一致性检查。
- 优先使用本机记住的校服实例，其次使用符合条件的当前所选实例；只有一个符合条件时自动选中。多个候选且尚未选定时，在校服行选择一次，之后记住。实例删除或校服地址、当前周目、客户端版本要求变更后重新匹配。
- 支持直链 Modrinth `.mrpack` 或 MultiMC 客户端 ZIP（包括现有 GTNH 现代 Java 兼容流程）。下载网页、网盘分享页面和服务端压缩包不能直接作为客户端。Modrinth 按[官方格式](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack)应用 `client-overrides` 并排除仅适用于服务端的文件。
- 维护页可读取本地整合包的 Minecraft / 加载器信息与 SHA-256。填写校验值后，客户端必须匹配才继续；URL 更换但哈希相同时复用已安装版本。哈希留空时按整合包版本和下载地址判断，维护人员每次修改内容须递增整合包版本。
- 新周目、客户端要求、整合包版本或哈希变更，会建立 `SAUMCL-CLMC-…` 独立实例；不覆盖或删除旧实例、旧存档、模组与配置。仅在新实例未提供时复制旧实例的 `options.txt`、`optionsof.txt`、`servers.dat`，不自动迁移存档或混合新旧模组 / 配置。只改 IP、端口或公告不重装客户端。
- 安装期间显示进度，依赖下载可在下载任务页面暂停和继续。关闭准备窗口会取消，失败或取消均不进入启动流程。未完成的受管实例隐藏，失败时只清理该次创建的目录，保留旧实例与下载缓存以供重试。最终启动前重新读取校服配置，客户端配置变更则停止并提示重试。
- 地址为空、维护中、当前周目已结束、下载地址已填但整合包版本缺失或牛数量超过启动限制时，按钮禁用。没有填写下载地址时仍支持选择现有兼容实例。单次离线探测失败仍可尝试连接。
- 账户校验、Java 选择与文件检查沿用普通启动流程；尚未登录时仍需完成登录。成功发起启动时自动清空牛。

当前未配置真实校服地址，暂不能完成实际校服联机验证；维护人员填写地址并应用到本机预览后即可使用。

## 启动页服务器列表

- 校服固定为第一项，即使尚未填写地址也保留，显示下一周目 20。
- 服务器与日历磁贴均可拖动标题栏移动，拖动右边、下边和右下角调整大小；松开后记住本机位置和尺寸。拖动时其他磁贴保持原位，松手后就近避让；缩放遇到邻近磁贴或屏幕边界时停止。窗口变小时在可见区域内调整尺寸，内容确实放不下时在磁贴内部滚动，为游戏启动按钮留出空间；恢复大窗口时沿用保存的布局。操作及后续磁贴规范见 [启动页磁贴](home-tiles.md)，独立于已停用的扩展插件。
- 其他服务器通过现有服务读取各实例的 `servers.dat`；不改写游戏文件。
- 相同地址合并为一行，保留所有来源实例供选择。裸域名与显式的 `:25565` 不合并，因为裸域名可能使用不同端口的 SRV 记录。
- 每分钟及页面重新可见时刷新，可手动刷新。连接时显式使用所选来源实例，沿用现有启动流程及放牛时的启动限制。
- 未填地址不计离线时间。自动模式下，首次失败记为离线；超过 48 小时且本次仍检测失败时，显示「当前周目已结束」。重新连通会重置计时，地址或周目变化会开始新记录。
- 维护人员可以显式标记进行中或已结束，优先于自动判断。

统一离线起始时间 `offlineSince` 为带时区的 ISO 时间。它由维护人员填写并发布后，各玩家可依据同一时间判断；未填写时使用各设备本机观察记录，跨重启保留。若本机在该时间之后实际探测到在线，旧的离线起始时间不再用于本次故障。该规则是用户选定的显示规则，不等同于持续运行的服务器监测。

## 玩家配置同步与发布边界

数据流为「维护草稿 → 本机预览 → 发布到固定的 GitHub 静态配置地址 → 玩家定时读取」。校服地址、周目和公告只需更新配置，无需重新发启动器。发布需要对应的 GitHub 写入权限，本地 Key 不包含 GitHub 凭证。

玩家统一读取 `https://raw.githubusercontent.com/Supaio/SAUMCL/main/public/campus-server.json`，请求沿用启动器的 User-Agent 与下载代理，失败时回退到已缓存或随包配置。维护人员保存并导出 `campus-server.json`，由具备仓库权限的人员更新自己仓库 main 分支的 `public/campus-server.json`，玩家在进入页面、手动刷新及每分钟刷新时接收更新，无需部署接口或重新发启动器。本机预览优先于公开配置，保存 / 导出本身不会上传。公开同步需要对应文件进入 main 分支后才能生效。当前真实地址与客户端整合包尚未填写，实际校服联机仍待配置后验证。

Indev 19.3 在用户明确要求上传前只在本地开发与验证，不推送源码、标签、配置、构建产物或远端草稿。

授权保存在应用数据目录的 `maintenance/authorization.saumclkey`，草稿在同目录的 `campus-draft.json`。授权不写入普通启动器配置，避免配置分享或便携包分发时带上授权。草稿导出不包含授权、签名私钥、GitHub 凭证。

## 本机签发工具

工具使用 Node.js 自带的加密模块及项目既有的 Rust 签名验证依赖，无需部署在线验证接口。只把签名公钥嵌入启动器，私钥由所有者保管。口令仅通过不回显的交互式终端输入，不使用命令参数、环境变量或日志传递。

以下路径均为示例。私钥和签发出的授权文件必须保存在 SAUMCL 专案之外；工具会检查路径，并拒绝覆盖已有文件。

### 首次初始化（仅项目所有者）

```powershell
node scripts/maintenance/keys.js init --dir "F:\SAUMCL-owner"
```

按提示设置保护口令后，在该目录保存加密私钥 `maintenance-private.pem` 和公钥 `maintenance-public.pem`。只有公钥会追加至 `src-tauri/assets/maintenance/trusted-keys.json`。

重新建置启动器，才能验证由该私钥签发的 Key。未初始化时，公钥清单为空，维护入口显示未配置，默认拒绝解锁。专案不带演示 Key 或可用于正式授权的测试私钥。

不要在每次更新或人员交接时重新初始化。保管好已有的加密私钥和口令，以便持续签发；后续启动器版本保留对应公钥即可继续验证旧授权。

### 为维护人员签发

```powershell
node scripts/maintenance/keys.js issue --private-key "F:\SAUMCL-owner\maintenance-private.pem" --name "维护人员名称" --out "F:\SAUMCL-owner\maintainer.saumclkey"
```

只将对应的 `.saumclkey` 文件发给维护人员，他们可在维护页直接导入。不要分发私钥或口令。工具不会把授权内容打印到终端。

## 验证

```powershell
node scripts/qa/maintenance-key-regressions.mjs
cargo test --manifest-path src-tauri/Cargo.toml --locked --test maintenance_regressions
cargo test --manifest-path src-tauri/Cargo.toml --locked --test campus_regressions
```

测试临时在内存生成签名材料，不使用生产私钥。覆盖长期授权、错误用途、篡改签名、追加公钥兼容、重启后验证、本机退出、未授权时拒绝草稿操作、导出内容不含授权等。

离线 Key 可被转发，无法即时远程撤销；开源客户端也可能被改动来绕过入口。它用于正常客户端的维护模式识别，不承担仓库发布授权。

实现参考：[jsonwebtoken 验证配置](https://docs.rs/jsonwebtoken/10.3.0/jsonwebtoken/struct.Validation.html)、[Node.js 签名模块](https://nodejs.org/api/crypto.html)。
